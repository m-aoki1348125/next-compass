# next-compass

[English](README.md)

Claude の返答が終わるたびに、**次の指示を 4 方向で予測**して入力欄の上に並べる
[Claude Code mod](https://code.claude.com/docs/en/plugins/mods/overview) です。番号キー 1 つで送信できます。
横の「意味空間マップ」には 4 択と追加の候補が類似度の空間に置かれ、候補の間をクリックすると
「その中間」の指示を作ってくれます。

選び続けるだけで、意図どおりにプロジェクトが進む。それがこの mod の目的です。

```
✦ 次の一手   入力欄が空のとき 1〜4 で送信 · ✎ は入力欄に入れて手直し · /compass でマップ
↑ エクスポート機能を仕上げて PR を作って                              ✎
→ CSV に加えて JSON 出力にも対応して                                  ✎
↓ 出力ファイルを実際に開いて確認して                                  ✎
← エクスポートのテストを追加して                                      ✎
```

## 仕組み

1. **Claude が作業している間**に、高速なモデル（haiku）が直近の会話の要約（キャッシュ済み）から
   候補を 6〜12 個用意します（要約は短く、同じ呼び出しで共有します）。マップには、ツール呼び出しごとの光が流れる空間が描かれます。
2. **返答が終わった瞬間**に、候補から 4 つを手元の計算で選んですぐ表示します。類似度空間で最も
   離れた 4 つで、`goal` を登録していればそれに近い候補を必ず含めます。その後、最終回答に合わせて
   高速モデルが選び直し、その場で差し替えます。本家 Claude Code の Tab 予測も届けば候補に加わります。
3. **マップの配置**はモデルではなく mod 自身が計算します。候補の文を文字 n-gram と単語で比べ
   （TF-IDF コサイン）、古典的 MDS で 2 次元に置き、前のターンの配置に向きを合わせるので
   マップが回転しません。同じ候補なら、いつも同じ場所です。4 択は置かれた位置が向く方向
   （上・右・下・左）を受け取り、モデルは方向の名前だけを付けます。
4. **候補の間を指す**と、キャプションに表示した割合どおりに近い 3 候補を混ぜた指示を 1 つ作ります。
   1 回目でマップの下に表示し、同じ位置でもう 1 回クリック（Enter）すると送信します。
   Shift を押しながらなら入力欄に入ります。

送られる文は、必ず読んだ文です。帯の幅に収まらず `…` で切れた択は、送信せず入力欄に入ります。

## インストール

```bash
claude plugin marketplace add m-aoki1348125/next-compass
claude plugin install next-compass@next-compass
```

クローンから 1 セッションだけ試すには `claude --plugin-dir ./next-compass` です。
インストール前に `claude plugin validate ./next-compass` で、この mod が何を呼ぶかを一覧できます。

## 使い方

| 操作 | 結果 |
|---|---|
| 入力欄が空のとき `1`〜`4`、または択をクリック | その指示を自分の指示として送信 |
| 択の横の `✎` | 入力欄に入れて手直し |
| マップ：クリック、または矢印キー＋Enter | その位置の指示を作り、マップの下に表示 |
| マップ：同じ位置でもう一度クリック／Enter | 送信（Shift で入力欄へ） |
| マップ：`1`〜`4` | その択を入力欄に入れる（マップには全文が出ないため） |
| `/compass goal <目的>` | 4 択が近づく目的を登録。`/compass goal` で消す |
| `/compass map` · `hide` · `show` · `refresh` | マップを開く、帯を隠す／出す、4 択を作り直す |
| `/compass stats` | 次の一手がどれだけ採用されたか（セッションをまたいで集計） |
| `/compass demo` | 16 秒のデモ。モデルは呼ばず、何も送信しない |

マップのペインは、幅の広い端末（約 144 桁）か デスクトップアプリで transcript の横に表示されます。
入力欄の上の帯はどこでも使えます。

## 設定（`/config`）

| 設定 | 値（太字が初期値） | 意味 |
|---|---|---|
| `language` | **`auto`** / `ja` / `en` | UI の言語。`auto` は Claude Code 本体の `language` 設定に従う |
| `keyMode` | **`number`** / `arrow` | `number`：空の入力欄で 1〜4。`arrow`：十字に並べ、帯にフォーカス（`ctrl+x tab`）してから矢印キーで選ぶ |
| `generator` | **`haiku`** / `sonnet` / `opus` / `fork` | 4 択と中間の指示を書くモデル。`fork` はセッション自身のモデルで会話全体を読む |
| `showMap` | **`true`** / `false` | セッション開始時にマップを開く |
| `extraCount` | **8**（0〜16） | 4 択のほかにマップへ置く候補の数 |

作業中の候補の準備と最終の選び直しは、常に haiku を使います。

## プライバシー

この mod が送るものはすべて Claude Code 自身のモデル呼び出し（`$.model.complete` / `fork`）を通り、
セッションと同じプロバイダへ届きます。ほかの場所へは何も送りません。`haiku` / `sonnet` / `opus` では、
直近 12 メッセージの要約（各数百文字に切り、呼んだツール名と主な引数：ファイルパス、コマンド、検索パターン、
サブエージェントへの依頼文）、登録した目的、Claude の最終回答の末尾、本家の Tab 予測、候補の文を送ります。
ツール引数のうち、よくある形の認証情報（`KEY=値`、`token: 値`、`Authorization: Bearer …`）は送る前に伏せ字にしますが、
URL 内のパスワードやフラグの後ろのトークンなどは伏せられません。要約は会話そのものと同じ扱いだと考えてください。
`fork` では 4 択と中間の指示はセッション自身のモデルが会話全体を読んで作りますが、作業中の候補の準備と最終の選び直しは
haiku に要約を送って行います。セッションをまたいで保存するのは `/compass stats` の集計値 4 つだけです。

会話の要約は「データ」として囲んで送りますが、モデルがその中の文に引きずられる可能性は残ります。そのため mod は
次の規則で動きます。帯は全文を表示できた択だけを送信し、マップは混ぜた指示をその位置に全文描けたときだけ、
もう一度同じ位置を選んだら送信し、それ以外は入力欄に入れて読んでもらいます。指示によって Claude が行う操作には、
Claude Code 本体の許可確認がそのまま働きます。

空の入力欄で数字だけを打つと、帯のその番号の択が押されます。Claude が番号付きの質問をしてきた直後は、
「1番で」のように言葉を添えて打つか、`keyMode` を `arrow` にしてください。

## 必要なもの

- mod に対応した Claude Code。2.1.301 で開発・確認しました。マップは端末とデスクトップアプリで描画されます。
- 組織の設定で利用者による mod のインストールが禁止されていることがあります。インストール後に `/compass` が
  なければ管理者に確認してください。

## 既知の限界

- 類似度空間は候補の**文**を比べるもので、意味そのものではありません。同じことを別の言い方で書いた
  2 つの指示が離れて置かれることがあります。決定的で速いことをマップのために優先しました。
  モデルによる補正は今後の候補です。
- `fork` は会話全体を読むため遅くなります。速さのため、既定は要約を読む `haiku` です。
- 会話の要約ブロックにはプロンプトキャッシュの印を付けていますが、1 回の生成の呼び出しは並列で、要約の範囲も
  ターンごとに動くため、キャッシュが効くのは追加の節約にとどまります。速さの中心は先読みと手元の計算です。
